# v1.1.0 릴리스 기록

2026-11-23. PC 선회 시나리오, 영어 GUI, 선택적 STM32 성능 계측과 검증 자료를 포함한다. 릴리스 대상은 **관측한 부하에서의 STM32 보드·전송·증거 검사**다. PC 미송신·RTT는 릴리스 차단 조건이 아니며 보드 지연·오류·무결성 기준은 완화하지 않았다.

## 포함한 변경

- PC 표적의 일정 선회율 원호, bank/TAS 변환과 구간별 직진·선회 시나리오.
- 영어 GUI·Python 주석 및 Python 코딩 스탠다드, 실제 보드 GUI 캡처.
- RX/ISR/parser/TX·추정기 시간, scheduler 비유휴와 앱 스택 관측. ISR은 유한 원시 캡처만 수행하고 집계는 스레드에서 처리한다.
- 선택적 계측은 활성/비활성 hook으로 분리해 UART·handler 코드의 흐름을 유지한다. 일반 이미지에는 PERF 수집기를 넣지 않는다.
- UART 처리와 파일 기록을 분리한 유한 비동기 기록 큐, 저장 실패·누락 검증.
- 보드/전송/증거, PC RTT, 요청 입력 부하의 판정 분리. 호스트 입력 중단을 보드 RESET 결함으로 오분류하던 시험기 수정.
- 송신 시한이 지난 뒤의 불필요한 `sleep(0)` 제거. 지연 시한·주기·보드 합격 한계는 유지했다.
- [40초 무음 GUI 재생 영상·5개 분석 그래프·수치 표](analysis/2026-11-23/README.md). 영상은 저장된 실보드 세션 재생이며 새로운 실시간 보드 실행이 아니다.

## 오류 이력과 후속 범위

| 항목 | 현재 분류 | 처리 |
|---|---|---|
| 시한 경과 후 `sleep(0)` | 확인된 시험기 결함, 수정·회귀 검증 완료 | 경계4개 시험: 수정 전2개 실패, 수정 후4개 통과 |
| 과거 CRC 2건 | **조치 후 비재현·해결 추정, 원인 미확정 이력** | 이전 계측 코드의 IRQ 차단·ISR 집계에 따른 수신 방해를 우선 가설로 기록. 물리 링크 오류도 배제하지 못한다. 수정 후300초·30분·최종60초에서 비재현. 별도 이슈는 두지 않는다. [릴리스 검증과 실패 분석](release-v1.1.0.md) |
| PC 미송신 | 현재도 관측되는 PC 입력원 한계, STM32 결함 아님 | 30분943개, 최종60초10개. [v1.1.1 PC 시험기 개선 #8](https://github.com/SungJaeYu/radar-tracking-bench/issues/8) |
| 무누락50Hz 전체 입력·물리 UART 경계·WCET | 이번 릴리스에서 입증하지 않은 범위 | [검증 경계](stm32-performance-coverage.md). `requested_profile_qualification=inconclusive`, `full_coverage=false` 유지 |

PC가 아예 보내지 않은 입력과 전송 후 응답 누락은 다르다. 실제 보낸 입력의 응답 누락·CRC·큐 오류·보드 시간/자원 위반은 계속 실패다. 호스트만의 지연을 이유로 보드 오류를 면제하지 않는다.

릴리스 표식은 저장소의 `v1.1.0` 태그이며 main에 통합한다. [변경 이력](../CHANGELOG.md)과 [프로젝트 보드](https://github.com/users/SungJaeYu/projects/1)를 함께 제공한다. 다음 PC 송신 정책 변경은 #8에서 먼저 검토하며 이번 릴리스에 추가 구현하지 않는다.

## 실패 분석 근거

과거 CRC2건의 우선 가설은 이전 PERF 계측의 ISR 집계와 IRQ 차단 중 통계/snapshot 처리에 의한 수신 방해다. 당시 UART ORE/FE/NE·수신 바이트·선로 측정이 없어 인과관계는 확정하지 못했다. 배선·접촉·잡음도 배제하지 못한다. 조치 후300초·30분·최종60초에서 비재현했으며 현재 분류는 해결 추정·원인 미확정 이력이다.

초기30분 실행의 최대 RTT220.246ms는 송신 간격219.419ms와, IRQ 보완300초의 최대 RTT328.516ms는327.317ms 공백과 겹쳤다. 이는 호스트 실행 지연의 증거이며 모든 RTT 꼬리의 원인을 하나로 특정하지 않는다. 시험기에서는 CRC 중단의 실패 분류 누락, 마지막 주기 요약과 최종 송신 개수의 불일치 판정, 정상 저장을 불완전 기록으로 오분류하던 경로를 수정하고 회귀검증했다.
