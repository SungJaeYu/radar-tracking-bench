# v1.1.0 마무리 사전 시험

**후속 상태:** 이 문서는 당시 실행과 판단의 기록이다. [최종 v1.1.0 범위](../../release-v1.1.0.md)에서는 PC 미송신을 STM32 릴리스 차단 조건으로 사용하지 않는다. 시한 경과 sleep은 [후속 수정·60초 검증](../host-pacing-fix-2026-11-23/README.md)에서 보완했다. 원시 결과와 당시 readiness JSON은 변경하지 않았다.

2026-11-23, `feat/tracking-benchmark`, 기준 커밋 `20f069f` 위 작업본.

**60초 실보드의 관측 부하·복구 검사는 통과했다.** PC가 예정 입력 3,000개 중 5개를 보내지 못해 요청 50Hz 전체 입력 조건은 미확정이다. 이 상태에서는 30분 전체 부하 검증으로 진행하지 않았으며 릴리스 완료 선언·커밋·푸시·main 병합·태그도 수행하지 않았다.

후속 [미송신 원인 조사](../host-pacing-cause-2026-11-23/README.md)에서 UART 없는 타이머 시험으로도 실행 재개 지연과 슬롯 누락을 재현했고, 기존 시험기의 시한 경과 후 `sleep(0)` 추가 대기도 관측했다. 아래 원본 시험의 판정은 유지한다.

- 데이터 `/dev/cu.usbserial-A5069RR4`, 콘솔 `/dev/cu.usbmodem11203`. 시작·종료 시 포트 점유 프로세스 없음.
- [실행 로그](preflight-60s-run.log), [실제 인자·이미지 해시](preflight-60s/metadata.json), [결과](preflight-60s/results.json), [원시 기록 대조](preflight-60s/audit.json).

## 입력 누락의 확인 범위

[입력 간격 분석](preflight-60s/input-gap-analysis.json)에서 센서 시각 슬롯과 PC write 직전 시각을 대조했다.

| 이전→다음 센서 시각 | 미송신 슬롯 | PC write 시각 간격 |
|---|---:|---:|
| 1,200→1,240ms | 1개 | 43.426ms |
| 6,020→6,060ms | 1개 | 57.880ms |
| 15,860→15,920ms | 2개 | 53.096ms |
| 31,540→31,580ms | 1개 | 52.778ms |

시험기는 다음 예정 시각보다 20ms 이상 늦으면 그 슬롯을 건너뛴다. 몰아서 따라잡는 입력을 보내지 않는 기존 동작이다. 원시 송신 wire와 samples CSV가 일치하므로 이 5개는 응답 유실이 아니라 송신하지 않은 입력이다. 지연을 만든 정확한 앱·OS 스케줄링·I/O 원인은 이 기록으로 분리할 수 없으며, PC write 시각도 물리 UART 도착 시각은 아니다.

입력 누락 없는 조건을 마련한 뒤 60초 사전 확인과 30분 요청 부하 시험을 수행해야 한다. 합격 기준을 바꾸거나 입력 누락을 보드 합격으로 간주해 릴리스를 완료하지 않는다. 검토용 브랜치 게시 여부는 릴리스 완료와 별도로 결정할 수 있다.
