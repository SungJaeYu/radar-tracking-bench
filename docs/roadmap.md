### 판정 변경과 측정 경계

- PC 송신 간격은 OS 스케줄링·프로세스 부하·I/O 대기 등 호스트 영향을 받습니다. 실제 송신률·최대 간격·건너뛴 슬롯을 기록하며, 슬롯 누락이나 기간 미달은 요청50Hz 부하 검증을 미확정으로 만듭니다. 이것만으로 관측 부하에서의 STM32 실패를 뜻하지는 않습니다.
- **PC write 직전 → 대응 TRACK이 포함된 read 직후**의 왕복 지연은 호스트 경로 진단입니다. **p99 ≤20ms, 최대 ≤100ms** 한도는 유지하지만 STM32 합격·릴리스 gate로 사용하지 않습니다. 호스트·USB·UART도 포함하므로 MCU만의 처리시간으로 해석하지 않습니다.
- 현재 `passed`는 보드 내부·전송·증거의 `board_qualification`과 같으며 관측 부하에 한정됩니다. `requested_profile_qualification`은 요청 기간 전체·50Hz 슬롯 누락0까지 요구합니다. 보드 지연20ms, scheduler 비유휴≤80%, 앱 스택별 최소 여유25%와 응답 대응·순번·오류·폐기 검사는 유지합니다. [현재 확장 계측 계약](stm32-performance-coverage.md).
- 11월 19일 원본 실행은 당시 호스트 송신 간격137.581ms 때문에 실패했습니다. 11월 18일 RTT 최대164.128ms를 포함해 과거 값과 원본 판정은 보존하며 새 정책으로 원시 기록을 덮어쓰지 않습니다. 과거30분 시험에는 현재의 모든 확장 계측이 없으므로 새 요구의 통과 증거로 승격하지 않습니다.
- 고정 방위각·각도 잡음 0에서의 평가입니다. 각도 기동·잡음, 실제 센서, 최대 지속 부하, WCET·실운용 성능을 증명한 것은 아닙니다. 정상 부하와 의도적인 오류 주입의 결과는 각각의 기록 범위로 읽습니다.

위 V1 기준선과 별도로, 후속 [잡음100회·순간 이상치49회 실보드 평가](hardware-test-2026-11-19-noise-spike.md)를 완료했습니다. 고정 방위각의 각도 잡음과 주입 후 복귀를 확인했으며 각도 기동·동시 양축 잡음은 추가 범위입니다.

## 추정기 결합 기법: v1.2.0 이후 검토 후보

현재 v1.2.0의 기존 추정기·CV-EKF·CT-EKF 동일 입력 비교 범위는 유지한다.
다음 항목은 후속 검토 후보이며 구현 완료나 STM32 탑재 확정을 뜻하지 않는다.

- **IMM**: CV/CT 등 여러 운동 모델의 필터를 병렬로 운용하고 모델 확률에 따라 혼합한다. 먼저 구현한 CV-EKF·CT-EKF를 재사용해 직선↔선회 전환의 정확도·응답성과 계산 비용을 비교한다. [IMM 설명](https://www.mathworks.com/help/fusion/ref/trackingimm.html).
- **Particle Filter (PF)**: 순차 몬테카를로 입자·가중치로 상태 분포를 표현하는 추정기다. 비선형·비정규 조건에서의 이득과 입자 수에 따른 정확도·실행 시간·메모리를 PC에서 먼저 평가한다. [추정 필터 비교](https://www.mathworks.com/help/fusion/ug/introduction-to-estimation-filters.html).
- **Rao–Blackwellized Particle Filter (RBPF)**: 일부 상태는 입자로 표현하고 조건부로 해석 가능한 나머지는 칼만필터 등으로 계산한다. 먼저 상태 모델의 분해 가능성을 확인하며 PF와 KF를 임의로 평균하는 방식으로 구현하지 않는다. [원 논문](https://arxiv.org/abs/1301.3853).

여러 seed로 잡음 입력을 반복하는 **몬테카를로 성능 평가**와, 몬테카를로를 사용하는 **추정 알고리즘**은 구분한다. 여러 센서의 정보를 결합하는 센서 융합도 별도 요구사항이다.
모든 후보는 같은 정답·측정 입력에서 오차·거부·추적 유지·전환 응답을 비교하고,
현재 estimator API 및 추적 상태 관리를 재사용할 수 있는지 검토한다.
STM32 적용은 실제 실행 시간·메모리 예산을 확인한 뒤 결정한다.
